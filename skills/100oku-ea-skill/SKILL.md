# 100oku EA Skill

このEAは「100億円トレーダー」手法マニュアル原典PDF(247ページ)の裁量ロジックをコード化したものである。
Codex監査役として `CheckEntry()=true` の妥当性を判定する際は、以下を必ず参照すること。

- `docs/codex_auditor_checklist.md` … 監査5項目・出力JSONスキーマ(判定の実務手順)
- `原典定義_全方向一致とライン.md` … 原典PDFの該当行番号付き定義(最上位のリファレンス)
- `IMPLEMENTATION.md` … EA実装のA〜G基準表(原典定義をコードに落とした結果)
- `docs/codex_examples/BTCUSD/summary_*.md` … 実際のリアルトレード解説10本の全文要約(本セクションの一次資料)

> **このファイルは Claude Code の作業規律の正本です(検証規律・監査役ロジック・実装規律)。**
> 検証結果の数値は持ちません。数値の正本は `docs/pending_hypotheses.md` です。
> 原典PDFの確認結果の正本は Google Drive の `100億j_share/報告_*.md` です。
> 同名のスキルが Claude 側(チャット側)にもインストールされていますが、そちらは
> 仮説設計用で役割が異なります(検証済み/棄却済み一覧の要約・原典記述の要約・索引が中心)。
> 内容が重複しないよう、この分担に従ってください(2026-07-28確定)。

## 検証規律(プロジェクト確定原則)

### 検証順序の絶対則:定義の忠実性 → 実装 → 統計(順序を逆にしない)

**確定日:2026-07-22(PH-30/PH-31の失敗から)**

#### ルール

EA条件・フィルターの採否を、**数値結果だけで判断してはならない。**
必ず以下の順序を守る。

```
① 原典の実例チャートを見て、定義の忠実性を確定させる
      ↓
② 定義が確定してから実装する
      ↓
③ 実装後に統計検証を行う
```

**逆順(実装 → 統計 → あとで定義を確認)は禁止。**

#### 具体的な行動規範(Claude・Claude Code 共通)

1. **チャート画像が生成されたら、必ず目で見る。** 数値レポートだけで採否を判断しない
2. **チャートを見る前に `docs/master_pre_chart_checklist.md` を開く。**
   「見て気づく」ではなく「11項目に照らして確認する」の順序で行う
3. **原典の実トレード記事の該当チャートと並べて比較する。**
   「良さそう」ではなく「100億さんの記事のこの形と一致しているか」で判断する
4. **一致していない点があれば、統計が支持していても、そう指摘する**

#### なぜこのルールができたか(PH-30/31の経緯)

`h4_trend_confirmed`(H4のダウ理論トレンド転換確認)を実装した際、
順序を逆にしたために大きく遠回りした。

- **PH-30**:定義を「安値切り上げのみ」として実装 → 統計は支持
  (BTC 78局面中、採用群39件が勝率53.8%/+0.615R/DD3.0Rとベースライン全指標を上回る。
  ETHでも方向性が再現)
- **しかし**:原典のETH記事(2025.12.9)のチャート画像を実際に見たところ、
  「4時間足安値切り上げ」と「戻り高値超え」が**別々のラベル**として図示されており、
  原典が「トレンド転換」と呼ぶのは**戻り高値ブレイクまで含めた状態**だと判明
- **横断検証**(EURUSD9本・USDJPY4本・BTC10本・ETH3本)で確認した結果、
  原典の定義は一貫して2段階:
  「戻り高値ブレイクによる転換確定」→「その後に形成される**初押し**」
  安値切り上げ単独は、(a)転換前の早期エントリー根拠 か
  (b)転換確定後の初押し のどちらかであり、この2つを現行実装は区別できていなかった
- **PH-31**(原典に忠実な2段階定義で再実装):誤検知は解消したが、
  採用群が13件まで絞られ「サンプル不足により判定不能」

#### この失敗から抽出される教訓

> **「効果が確認された」は、その指標が原典の概念を正しく捉えている
> ことの証明にはならない。** たまたま似た方向に相関しているだけかもしれない。

`d1_ma20` が唯一生き残った数値フィルターであり続けている理由は、
数字が良かったからではなく、**原典概念(グランビルの中のグランビル)に
直接接続していると言語化できたから**である。

逆に、原典から少しズレた代理指標は例外なく失敗している:
TrendScoreFilter / PH-01(MA伸び切りの二値化)/ PH-03(週足MA方向)/
PH-04 / PH-08(乖離の単独数値化)。

したがって、**統計的な有効性より先に「原典の何を捉えているか」を
実例チャートで確認する**のが、このプロジェクトにおける正しい順序である。

#### 補足:H4とD1では「形」が違う(2026-07-26 追記)

D1の横断検証で判明した重要な構造差。

- **H4**:記事の時系列の中で「戻り高値を超えた瞬間」という**確定イベント**が起きる
- **D1**:記事冒頭で「日足は上昇トレンド中」と**継続的な背景(状態)**として
  提示されるだけで、確定イベントが描かれることは全26本中ゼロ

→ H4方式(イベント検出)をD1にそのまま転用するのは、原典の記述構造と整合しない。
`d1_ma20`(距離=状態を測る指標)がD1に対して機能してきたのは、
偶然ではなく**D1に対して正しい"形"の指標だったから**である可能性が高い。

時間足ごとに「原典がそれをイベントとして扱っているか、状態として扱っているか」を
確認してから、指標の形(イベント検出か、連続値か)を決めること。

## 監査役ロジック(BTCUSD10本から抽出)

対象10本(BTCUSD、日付順): 2024.7.6 / 2024.7.24 / 2024.7.28 / 2024.11.2 / 2025.2.23 / 2025.3.9 /
2025.3.28 / 2026.1.13 / 2026.1.18 / 2026.3.4。各ルールは「何本中何本に現れたか」を明記する
(全10本を通読した上での実測値。恣意的な代表例選びではない)。

### ルール1: 収束→拡散(グランビルの中のグランビル) — 10/10本で出現、最頻出パターン

- **内容**: 上位足MA(例: 4時間足MA)に対して下位足MA(例: 1時間足MA)が「収束(接近・横ばい)→拡散(乖離しながら伸び始める)」するポイントでエントリーする。これが隣接する時間足ペアで**2段重ね**(日足MA×4時間足MA、かつ4時間足MA×1時間足MA)になっている状態を「グランビルの中のグランビルの局面」と呼び、最高確信度の根拠として扱う。
- **原典/EA対応**: 原典定義1-2「大きな流れと小さな流れが"合致する瞬間"」に相当。EA基準では**D**(H1 20/80 SMAの収束後拡散)と**E**(波の時間的な入れ子)が該当。全時間足の全MAを完全整列させる要求ではなく、隣接ペアの合致を見る点が原典の核心。
- **根拠記事**: 全10本。特に「グランビルの中のグランビルの局面」と明言: 2025.2.23、2025.3.9、2026.1.13。「収束→拡散を獲りにいくトレード」と画像内に明記: 2024.7.24、2025.3.28、2026.1.18。「第3波の中の第3波」という入れ子表現: 2024.7.28。
- **監査で使う判定**: `higher_tf_ma_block`がfalseで、かつ隣接時間足ペア(最低1組、理想は2組)でMAの収束→拡散が確認できるかを見る。1組も無ければ`wave_position`を`unclear`寄りに倒す。

### ルール2: 上位足MA乖離の解消(逆張り的グランビル) — 8/10本で出現

- **内容**: 表面上のトレンド方向(日足が上昇/下降)と実際のエントリー方向が逆になる根拠として、「日足MAと週足MA(または4時間足MAと日足MA)が大幅に乖離しており、乖離は必ず収束するのがセオリー」という論理を使う。史上最高値到達時(2024.11.2)でもこの論理で逆張りショートしている。
- **原典/EA対応**: 原典定義1-3「日足MAまでの距離があればエントリーOK」の例外規定、および**B-2**(H4/D1 MA乖離が`k4×ATR`以上かつ乖離縮小方向)に直接対応。原典は「日足方向と逆でも日足MAまでの距離が十分あれば入ってよい」としており、BTCUSD実例はこれを反対方向のMA乖離にまで拡張して使っている。
- **根拠記事**: 2024.7.6(「乖離を埋めるのは絶対の法則」と明言)、2024.7.24、2024.11.2、2025.2.23、2025.3.28、2026.1.13、2026.1.18、2026.3.4。**出現しない例外**: 2024.7.28と2025.3.9は純粋なトレンドフォロー(上位足方向とエントリー方向が一致)で、乖離解消ロジックを使っていない。
- **監査で使う判定**: `weekly_daily_divergence`がtrueかつ`higher_tf_ma_block`がtrueの組み合わせは、原典的には**矛盾ではなくOK材料**(上位足MAが頭を抑えていても、乖離が大きければ「まだ距離がある」と読む)。両フラグを単純ANDでNGにしないこと。

### ルール3: ワンクッショングランビル第3波 — 9/10本で出現(2024.11.2のみ明示なし)

- **内容**: レートが上位足MAを一度ブレイクし、そのMAが逆側から support/resistance として機能し始める瞬間(=ワンクッション)を「第3波」の入口として使う。
- **原典/EA対応**: **B**(H4 20/180 SMA間距離・傾き・価格位置)と**D**(収束後拡散)の複合。「転換後の初押し/初戻し」というタイトルパターンの大半(2024.7.28、2025.2.23、2025.3.28、2026.1.13、2026.3.4)がこの型。
- **根拠記事**: 2024.7.6、2024.7.24、2024.7.28、2025.2.23、2025.3.9、2025.3.28、2026.1.13、2026.1.18、2026.3.4。
- **監査で使う判定**: `wave_position`を`first_pullback`と判定する主根拠。MAを一度ブレイク→そのMAに一度支えられた/抑えられた形跡があるかを画像で確認する。

### ルール4: ライン強度は2回では「強い」と言えない、3回以上タッチで強い節目 — 4/10本で3回以上を明示カウント(2026.1.18、2026.3.4、2025.3.9、2025.3.28)

- **内容**: 実例記事が「強いライン」として図示・強調するのは、ほぼ例外なく**3回以上**のタッチ(ピンク丸や四角枠で明示)である。2026.1.18の記事では4時間足ネックラインへの3回タッチ・1時間足で見ると5回タッチを重ねて強調し、2026.3.4では「3度高値をつけているライン」を明示的に利確目標にしている。2025.3.9では過去のレジサポ転換ラインでの複数回の攻防が四角枠で強調されている。
- **原典/EA対応**: **重要な不一致**。原典定義2-2は「強いラインとは過去に**何度も**そこで止められているか」であり、`原典定義_全方向一致とライン.md`は「2回は原典の『何度も』に当たらない…最低3回以上」と明記している。一方 `docs/codex_auditor_checklist.md` の項目2は現状「タッチ2回以上=意識ライン=強」となっており、**原典およびBTCUSD実例の実測(3回以上が"強い"の基準)と食い違っている**。EA基準では**C**(ピボット水平線への近接と過去反応回数)がこれに対応。
- **根拠記事**: 2026.1.18(3回・5回タッチを明示)、2026.3.4(3度高値ラインを明示)、2025.3.9(複数回攻防を四角枠で強調)、2025.3.28(3箇所の上値抑制を四角枠で強調)。ダブルトップ/ダブルボトム(2回タッチ相当)を根拠にした記事(2024.11.2、2026.3.4の1時間足ダブルボトム等)もあるが、これらは「ネックライン」という別カテゴリの型(2回でパターンとして完成する)であり、単独水平線の強度判定とは区別する。
- **監査での扱い**: このSKILL.mdでは知見として記録するのみとし、`docs/codex_auditor_checklist.md`の既存項目2の文言は変更しない(ユーザー指示によりchecklist構造は維持)。将来checklistを改訂する際は、この不一致を優先的に解消すること。

### ルール5: 複数種の抵抗/支持の重複(confluence) — 6/10本で明示

- **内容**: 水平ライン・トレンドライン・MA・ネックラインなど**種類の異なる**抵抗/支持が同じ価格帯に重なるほど、そのゾーンの信頼度を高く評価する。重なる箇所はエントリーのブロック要因(直上にあれば見送り)にも、利確目標(TPとして使う)にもなり得るため、位置関係(エントリーとTPの間か、エントリー直上か)で意味が逆転する点に注意。
- **原典/EA対応**: 原典定義2-1「レジスタンスラインが近すぎる場合は見送り」の判定精度を上げる補助情報。EA基準では**C**(ライン)と**G**(強いライン直前フラグ)の複合判定に相当し、**F**(TP選定)にも影響する。
- **根拠記事**: 2025.3.28(週足ダブルトップネックライン+日足下降トレンドラインが重なる水準で上値抑制)、2026.1.18(週足の過去安値ライン+4時間足ネックラインの重複、さらに直下に日足高値ラインを上限とするサポート帯というリスク側confluenceも同時提示)、2025.2.23(日足ダブルトップ+日足MA下向き)、2025.3.9(レジサポ転換ライン+日足MA下向き+週足MA大幅割れ)、2024.11.2(4時間足ダブルトップネックライン+日足・週足MA乖離+史上最高値ライン)、2024.7.28(レジサポ転換ライン+日足MAに対する4時間足MAの収束拡散)。

### ルール6: MAの傾き変化(水平→方向転換)を初動シグナルとして使う — 4/10本で明示

- **内容**: MAの絶対的な向きだけでなく、「下向き→水平」「水平→上向き」といった**傾きの変化そのもの**を、期間内トレーダーの需給バランス変化のシグナルとして使う。2025.3.28と2026.3.4では「MAの傾きが変わるということは、その期間のレートの平均値の変化を示しており、期間内トレーダーの行動が変化してきたということ」と明示的に解説している。
- **原典/EA対応**: **B**(180SMAのATR正規化した傾き)に直接対応。EAが傾きを数値化して閾値判定する設計は、この実例の「傾きが完全に反転する前、水平化した時点」を捉える意図と一致する。
- **根拠記事**: 2024.7.6(「ガンガンに下向きだった1時間足MAが完全にその勢いを無くし、逆に上を向き始めてきています」)、2024.7.28(「水平から上向きになりつつある4時間足80MA」)、2025.3.28(「4時間足MAの傾きが水平から下向きに変化しつつあり」)、2026.3.4(「日足MAの傾きが下向きから水平に変化」)。
- **監査で使う判定**: `wave_position`判定の補助材料。傾きが**既に十分に方向転換して走り切っている**場合は`late_trend`寄り、**水平化した直後〜転換直後**の場合は`first_pullback`寄りとする。

### ルール7: 計画崩れからのリカバリー — 5/10本で出現

- **内容**: 当初想定していたエントリーポイント(ネックライン抜け等)が不成立(チャート未確認による見逃し、または価格がその手前で反転しパターンが崩れる)になった後の対応が、記事ごとに異なる形で正直に共有されている。パターンは大きく3種:
  1. **遅延エントリー**: 理想ポイントを逃し、後から成行で追いかける(2024.7.24、2024.11.2、2025.2.23)。
  2. **先回りエントリー**: チャートを見られない時間帯を予測し、理想ポイントより手前で早めに建てる(2025.3.9)。
  3. **注文キャンセル→別根拠での再エントリー**: 当初の型(ダブルボトムのネックライン超え待ち)が安値割れで崩れた後、いったん注文をキャンセルし、**別の独立した根拠**(4時間足MAに支えられての下髭)が新たに成立してから成行で入り直す(2026.3.4)。
- **原典/EA対応**: 直接対応するEA基準記号はないが、原典の「見送りこそ価値」の精神(`原典定義_全方向一致とライン.md`末尾)と、**F**のRR再計算(エントリー価格が変わればSL/TPも引き直す)に関わる。3番目のパターン(2026.3.4)が最も原典に忠実で、崩れた型に固執せず新たな根拠の成立を待っている。
- **根拠記事**: 2024.7.24、2024.11.2、2025.2.23、2025.3.9、2026.3.4。
- **監査で使う判定**: バックテストやINDEX.md作成時、エントリー画像が「当初シナリオ通りの型」か「計画崩れ後の代替根拠による型」かを区別してnoteに残す。後者は前者よりconfidenceをやや下げるが、**新たな独立根拠が明示されていればNGにはしない**(単なる価格追いかけと区別する)。

### ルール8: 波動解釈の相違を許容しつつリスクを認識・ロット調整 — 2/10本だが原則として重要

- **内容**: エリオット波動が第3波か第5波か意見が分かれる局面(2024.7.28)や、上位足の反転リスク(押し目買い/戻り売りの再形成)を明確に認識しつつも、リスクをロットサイズで吸収してエントリーする(2026.1.18「資金管理の比率を引き下げ、通常よりもロット数を抑えてエントリー」)。
- **原典/EA対応**: `wave_position`が`unclear`であることは、単独では`entry: NG`の確定要因にしない。原典もリスクの存在自体は許容し、ポジションサイズで調整する裁量を残している。EA側は現状ロット調整の仕組みを持たないため、監査役はこの点を「本来は許容されるべきリスクだが、EAの固定ロット設計では吸収できない」という注記としてnoteに残す。

## 実装規律: Dの実装＝逐次・逆指値モデル(確定済み)

**Dは「確定足終値ベース」ではなく「逆指値(ストップ注文)モデル」で実装する。**
終値ベースだと突破ライン外にいる間ずっとD成立が続き、重複候補が大量発生する
(全期間で324件→84件に減ったのはこの重複除去が効いたため。減少は健全)。

### 実装ルール(リーク防止の核心)

1. **注文タイミング**: D事前条件が「不成立→成立」に切り替わった**確定足の終了後**に注文を置く(連続成立中は毎時間動かさない)
2. **注文ライン**: 直近の**確定済み**H1ピボットへ逆指値(前足までに確定したピボットのみ)
3. **約定判定**: **次足以降**の高値・安値で到達を判定。**同じ足の高安による即時約定は禁止**(リークになる)
4. **約定価格**: ピボット価格
5. **約定時の再判定**: 約定時にD条件を再要求しない(注文時に確定済み)。**ただしA/E/F等は約定足の直前までの確定情報だけで評価する**(約定足のOHLCで評価すると裏口リーク)
6. **Fの利確目標・しきい値は未変更**

### 高速版を実装するときの注意

- 高速版の事前判定に「約定時もH1トレンド・拡散・MA順序を再要求する旧D条件」を残すと、逆指値約定を落とす(過去に10件落ちた)。約定時は**逆指値到達だけ**を見るよう揃える
- ステートフルな注文モデルは分割並列だと過去を重複走査して破綻するため、全期間集計は**一方向の増分走査**で行う

### 残課題チェックリスト(実装時に必ず確認)

- [ ] **押し目の再アーム**: 1トレンド内で押し目を繰り返し取るのがこの手法の核心。D事前条件が押し目の収束フェーズでちゃんと「不成立」に落ちて再アームされるか。落ちないと2回目以降の押し目エントリーが全部消える
- [ ] **ギャップ約定**: ピボット価格固定だと足がピボットをギャップで飛び越えた時に実際より良い約定になる。買いなら `約定 = max(ピボット, 足の始値)` にしてバックテストを甘くしない
- [ ] **未約定注文の無効化条件**: トレンド反転／反対側ピボット形成／N本経過 のどれで失効させるか明示で固定
- [ ] **RR下限の妥当性**: RR 0.254 のような低RRで弾く時、それがトレーダーの実エントリー(お手本)なら、Fの目標割り当てか約定足評価のズレを疑う
- [ ] **リグレッションテスト**: 高速版＝素朴版の一致は直近1,000点窓でなく、過去にズレが出た全期間走査を固定値テストにしてロックする
