## 0. 用語と時刻の約束

- H1足の `timestamp` は足の開始時刻。H1足 `t` の終値が確定するのは `t + 1h`。
- D1・H4は `DecisionPipeline._resolve_indexes` で「H1足 `t` の確定時刻 `t+1h` より前に確定した最後の足」を参照する
  （`_index_before`）。当日・現在バケットの未確定D1/H4は参照しない。
- `i` = 逆指値を置いたH1足（`placed_at`）、`j` = 約定したH1足（`j > i`）。
- 「指標」= SMA・ATR・傾き・確定ピボット・ダウ方向・収束距離・反応幅など、終値または足全体から計算する値。

## 1. 4つの時点と参照可否

| 時点 | いつ | 参照してよい値 | 参照してはいけない値 | ここで決めること |
|---|---|---|---|---|
| 注文時点 | H1足 `i` の終値確定直後（`i+1h`） | H1: 足 `i` までの確定足（OHLC・指標・確定ピボット）。H4/D1: `_resolve_indexes(cutoff=H1[i].timestamp)` が返す確定足まで | 足 `i+1` 以降の値すべて。未確定のH4/D1足 | 逆指値価格（ピボット価格）・A/B/B-2/C/E/F/Gの採点・Dのセットアップ（MA720傾きを含む）・SL構造・TP構造・取消し条件 |
| 約定直前 | 足 `j` の始値が出た瞬間 | 注文時点の値 ＋ 足 `j` の**始値のみ** | 足 `j` の高値・安値・終値・指標 | ギャップ約定価格（§2）。始値で約定する場合はエントリー価格が始値になる |
| 約定中 | 足 `j` の内部 | 注文時点の値 ＋ 足 `j` の始値・高値・安値（到達判定のみ）。順序が必要なときは同じ時間帯の M15 足（`data\m15.csv`） | 足 `j` の終値、足 `j` を含めて計算した指標値（MA・ピボット・ダウ方向・ATRなど） | 約定したか／SL・TPに到達したか（§3）。**採点をし直さない** |
| 足確定後 | 足 `j`（または未約定の足 `k`）の終値確定後 | その足の終値・更新後の指標 | 次の足以降の値 | 注文の取消し・置き換え・新規注文（再判断はこの時点でのみ行う） |

補足:
- 約定中に終値・その足の指標で採点し直すと、既に通過したバー内の価格で約定させながら、約定後にしか分からない情報で
  可否を決めることになる（監査4-6）。これを禁止する。
- 未約定足の終値で注文を取消し・置き換えるのは「足確定後」の行為なので許される（§4の現行挙動）。

## 2. ギャップ約定

PH-44（`scripts/ph44_h1_dow_stoporder.py`）と同一の規則。

| 方向 | 約定条件（足 `j`） | 約定価格 |
|---|---|---|
| 買い逆指値 | `high_j >= 注文価格` | `max(注文価格, open_j)` |
| 売り逆指値 | `low_j <= 注文価格` | `min(注文価格, open_j)` |

- 注文を置いた足 `i` 自身では約定しない（`j > i`）。
- スプレッド・追加スリッページは扱わない（OHLCモデル）。
- SL・TPの**構造**（どのピボット・MAを使うか）は注文時点の確定足で選ぶ。ギャップでエントリー価格が始値に
  変わった場合のみ、その価格（約定直前情報）でSL/TP候補の距離・RRを計算する。非ギャップ約定では注文時点の計算と同一。
  ※この扱い（ギャップ時にTP候補の選び直しを許すか、注文時点のSL/TP価格を固定してRRだけ変えるか）は
  **未確定**。2026-10-08時点の全期間データでギャップ約定は0件（`docs/audit_20261008/gap_fix_verification.json`）。

## 3. 約定バー内のSL/TP

約定バー `j` から決済判定を始める（`j+1` からではない）。

### 3-1. H1 OHLCだけで決まる場合

買いで記す（売りは高安・不等号を反転）。`at_open` = 始値で約定（`open_j >= エントリー価格`）。

| 足 `j` の状態 | 判定 | 曖昧 |
|---|---|---|
| SLにもTPにも届かない | 決済なし。`j+1` 以降へ | — |
| `at_open`、SLのみ到達 | SL | いいえ（始値約定後の安値は必ず約定後） |
| `at_open`、TPのみ到達 | TP | いいえ |
| `at_open`、SLとTPの両方 | M15で解決（3-2） | 解決できなければ はい |
| 足の途中で約定、TPのみ到達 | TP | いいえ（TP > 約定価格 > 始値なので、TP到達は必ず約定後） |
| 足の途中で約定、SL到達（TPの有無を問わない） | M15で解決（3-2） | 解決できなければ はい（安値が約定前か後か不明） |

### 3-2. M15による順序の解決

- 足 `j` の開始時刻から1時間に含まれる M15 足（`:00 :15 :30 :45` の4本）を使う。
- 4本そろっていない、またはM15上で約定水準に届いていない（H1と不整合）場合は「M15欠損」とする。
- 時系列に走査し、最初に約定水準へ届いたM15足を約定M15足とする。約定M15足では3-1と同じ表を
  M15足のOHLCに適用する。約定M15足より後のM15足では、SLとTPの両方に届けば曖昧、片方ならその結果。
- 1時間内に決済が出なければ `j+1` 以降へ進む。

### 3-3. 曖昧の扱い

- M15でも判定不能、またはM15欠損のときは「曖昧」フラグを立て、**保守的にSL扱い**（-1R）とする。
- 曖昧件数は必ず集計に出す（`Trade.reason == "stop_ambiguous"`、`Metrics.ambiguous`）。
- M15は `run_backtest(..., m15=bars)`（CLIは `--m15`）で渡す。渡さない場合は
  3-1で順序が必要なケースがすべて曖昧（SL扱い）になる。
- `j+1` 以降の足でSLとTPが同じH1足に届く場合は、従来どおりSL優先（保守的）。この場合のM15解決は
  今回の対象外（**未確定**: 後続バーにもM15解決を適用するかは別途判断）。

### 4-1. 根拠の安値／高値割れによる取消し（2026-10-16 固定、MANABU承認）

根拠: 原典 2026-03-04（BTC/USD、記事32282）「ダブルボトムの安値を割ったので注文をキャンセル」。
`data/realtrade_cache/` で注文取消しを明記した記事はこの1件のみ（n=1＋論理的整合で採用）。
報告: `100億j_share/報告_20261016_注文取消し規則の原典照合.md`

> 買いの逆指値を置いた後、約定する前に、注文時点で確定していた直近のH1押し安値
> （＝その注文のSL水準）を価格が下回ったら、その注文を取消す。
> 売りは高安を反転する（直近のH1戻り高値を上回ったら取消し）。

| 項目 | 規則 |
|---|---|
| 取消し水準 | 直前に確定した足までの確定H1ピボットのうち、注文価格より下（売りは上）にある最も新しい安値（売りは高値）。足が確定するたびに更新する（§4-3、2026-10-17改訂。改訂前は注文時点で固定）。該当なしなら取消し水準なし |
| 判定に使う値 | 足 `k`（`k > i`）の安値（売りは高値）。ヒゲで割っても取消し。水準ちょうどは割っていない扱い |
| 判定の時点 | 足 `k` の確定後。取消しは足 `k+1` から有効（§1「足確定後」） |
| 同じ足で約定と割れの両方 | 始値が注文価格以上（売りは以下）なら約定が先。そうでなければM15（§3-2と同じ4本）で順に見て、先に起きた方を採る。1本のM15内で両方が起き始値で決まらない、またはM15欠損なら「曖昧」とし、**保守的に約定扱い**（約定バー内でSLにも届いているため、§3でSLまたは曖昧SLになる） |
| 件数 | 取消し・曖昧の件数を `DecisionPipeline.cancel_stats` に記録する |
| 取消し後 | 新しいセットアップ（False→True）が必要（従来の置き換え規則と同じ） |
| 入れないもの | 原典の「取消し後に成り行きで入る」部分（4時間足MA反発という別根拠）。今回は対象外 |

M15は `DecisionPipeline(params, m15=...)` または `run_backtest(..., m15=...)` で渡す。渡さない場合、
同じ足で約定と割れの両方が起きたケースはすべて曖昧（約定扱い）になる。

### 4-2. 注文価格の追随（2026-10-17 固定）

根拠: 原典 記事22285（ドルカナダ 2022.5.26）。売りの逆指値を置いた後、約定前に「1時間足レベルで高値と安値をつけてきた」ので、
見ていれば「売り注文を1時間足レベルの安値抜けに移動させ、損切りラインも1時間足レベルの直近高値に移動させていたはず」。
理由は「損切り幅を狭くできる」「仕掛け位置を早くできる」。BTC 2026-01-13 も、原典は注文時点より新しい直近高値のブレイクで入っている。
報告: `100億j_share/報告_20261017_引き金と取消し水準の追随.md`

> 買いの逆指値が未約定の間に、注文中のピボットより**新しく、かつ低い（手前の）**H1ピボット高値が確定し、その価格がまだ終値より上に
> あれば、注文価格をそのピボットへ移す。売りは高安を反転する。

| 項目 | 規則 |
|---|---|
| 判定の時点 | 足 `k` の確定後（§1「足確定後」）。`k` までの確定ピボット（`N_h1=3`）のうち最も新しい同じ種類のもの |
| 移す条件 | (1) そのピボットが注文中のピボットより新しい、(2) 注文価格より手前（買いは低い、売りは高い）、(3) 足 `k` の終値より先にある（買いは上） |
| 移さない場合 | 新しい節が注文価格より先（買いは高い）にあるとき。原典の目的（仕掛けを早く・損切りを狭く）に反するため |
| 新しい注文の有効開始 | 足 `k+1` から（§2の「置いた足では約定しない」と同じ） |
| 採点時点 | 変えない（`placed_at` のまま。§5）。移したのは注文価格だけ |
| SL | §5-1のとおり約定直前の最新の節（追随とは別に決まる） |
| 取消し水準 | §4-3で、追随後の注文価格に対する最新の節へ更新する |
| セットアップ消滅 | 従来どおり取消さない（原典に記述なし） |
| 置き換え（§4） | 新しいセットアップでの置き換えは従来どおり。そのときは追随の記録も消える |

`Params(order_follow=False)` で従来（注文価格を動かさない）に戻る。

### 4-3. 取消し水準の追随（2026-10-17 固定）

> 未約定の注文の取消し水準は、足 `k` が確定するたびに、`k` までに確定したH1ピボットのうち注文価格より先（買いは下）にある
> **最も新しい**ものへ更新する。足 `k+1` の安値がそれを下回ったら取消す（判定・同足の扱いは§4-1のまま）。

- 理由: 取消しは「エントリー根拠が崩れたら注文も消す」で、根拠が崩れる所＝SL（損切り記事8671「エントリー根拠が崩れる所」）。
  SLは§5-1で約定直前の最新の節にしたので、取消し水準も同じ選び方にそろえる。原典 2026-03-04 の取消しは、ブレイクを待っていた
  ダブルボトムの安値（割れる直前の最新の安値）を割った時点で、この定義と一致する。
- 注文価格が§4-2で移ったときは、移った後の価格に対する最新の節を使う。
- 取消し水準の更新は、取消し判定と同じく足確定後の情報だけを使う（§1）。
- `Params(cancel_follow=False)` で注文時点の水準に戻る（比較用）。

## 5. 採点時点（監査4-6の修正後）

- 約定足 `j` の判断（`evaluate(as_of=H1[j].timestamp)`）では、Dの「約定したか」だけを足 `j` の高安で判定する。
- A・B・B-2・C・E・F・G・点数・Dのセットアップ部分（MA720傾き）・SL/TP構造は、その注文の `placed_at = i` を
  cutoff とした確定足（`_resolve_indexes(cutoff=H1[i].timestamp)`）で採点する。
- 約定していない足の判断は、その足の確定後の判断（足確定後）として従来どおり当該足で採点する
  （Dが不成立なので actionable・厳格候補にはならない）。
- `placed_at` 時点の上位足が存在しない（データ先頭付近）場合は採点不能として D不成立扱い
  （`order_time_state_unavailable`）。
- 「注文時点（`placed_at`）」ではなく「約定足の直前の確定足（`j-1`）」で採点し直す案もありうる
  （足確定後の再判断として許される）。今回は指示どおり注文時点で採点した。どちらにするかは**未確定**。
- 注文時点はDのセットアップ成立足（H1ダウ方向＝取引方向）なので、A・EのH1ダウ条件はその時点で
  満たされている。約定足で採点していた時より A・E の通過が増えるのはこのため（閾値変更ではない）。
- 注文から約定までの経過は全期間で中央値5時間・最大198時間（有効期限がないため）。

### 5-1. SLの参照時点（2026-10-17 固定）

報告: `100億j_share/報告_20261017_SL定義の照合.md`

> SLは、**約定足の直前の確定足（`j-1`）までに確定した**H1ピボットのうち、約定価格より先（買いは下、売りは上）にある
> 最も新しいもの。注文時点（`placed_at`）のピボットではない。

- 原典の言葉: 「直近安値のちょっと下」（損切り記事 8671）、「1時間足レベルの安値切り上げポイントの少し下」（PDF p.162）。
  注文中に構造が変われば「損切りラインも1時間足レベルの直近高値に移動させていたはず」（記事22285）。
- 原典の図: 2026-03-04（ダブルボトムの安値＝4時間足安値切り上げ）、2026-01-13（ブレイク直前の小さな切り上げ安値）、
  2025-02-23（直前の小さな戻り高値）とも、SLは約定直前の最新の節。2026-01-13 の注文時点のピボット（90,370）では、
  原典より約1.5倍広い。
- `j-1` までの確定ピボットなので、約定足の情報は使わない（§1「足確定後」の値）。
- 「ちょっと下」の幅は原典に数値がない。従来どおりピボットの価格そのもの（幅0）。
- **取消し水準（§4-1）は今回は変えない**（注文時点の直近安値のまま）。原典 2026-03-04 の取消し（ダブルボトムの安値割れ）も
  「最新の節」と読めるので、取消し水準を同じ参照時点にそろえるのは次の1変数として別に行う。
- `Params(sl_at_fill=False)` で注文時点のSLに戻る（比較用）。A〜G・点数・TPの構造は従来どおり注文時点（§5）。

## 6. 候補判定の入口（監査4-1の修正後）

- 候補判定は `oku100.distribution.candidate_ready(decision, gate)` の1関数に集約し、集計
  （`scan_distribution`）とバックテスト（`run_backtest`）の両方から呼ぶ。
- `gate="actionable"`: 点数60以上＋D（現行バックテストの入口）。
- `gate="strict"`: A AND (B OR B-2) AND C/D/E/F（現行集計の厳格候補）。
- **採用は strict（2026-10-16決定）**。理由は原典への忠実性: strict は原典の「全方向一致」と各条件の成立を
  そのまま要求するが、actionable の「60点以上」は原典にない独自の閾値。成績では選んでいない
  （同日の全期間計数では平均Rは actionable の方が高い）。
- 既定値は `run_backtest`・`scan_distribution` とも strict。actionable は参考として `gate="actionable"` で残す。
- `oku100/cli.py backtest` は `--m15 data\m15.csv` でM15を渡せる（2026-10-16追加）。

## 7. 利確（分割利確、2026-10-16 固定）

根拠: 原典BTC/USD記事11本の照合（`100億j_share/報告_20261016_分割利確の原典照合.md`）。
分割決済11/11、利確先は場所で決める11/11、第1目標がH4レベル10/11、第1目標に日足MA 0/11。
報告: `100億j_share/報告_20261016_分割利確の実装.md`

> 利確先は、注文時点の確定足から取引方向にある構造を最大3つ選ぶ。
> T1・T2 = H4レベルの構造（近い順に2つ）、T3 = T2（T2がなければT1）より先で最も近い日足レベルの構造。
> 目標の数で等分して決済し、各目標はラインの手前に指値で置く。追随・裁量決済・SL移動はしない。

### 7-1. 規則

| 項目 | 規則 | 出どころ |
|---|---|---|
| 時点 | 注文時点（`placed_at`）の確定足（§5と同じ状態）で選ぶ。除外判定・比率・Rは約定価格（§2のギャップ込み）で計算 | §1・§2 |
| H4の構造 | H4の確定ピボット（`N_h4=3`、高値・安値の両方、全履歴）、H4 20SMA、H4 80SMA | ピボット幅・全履歴は**自分たちの設定**（既存 `_target` と同じ）。20SMA＝原典の無印「4時間足MA」（H1 80MA相当として既存）、80SMA＝原典本文の「4時間足80MA（=320MA）」。SMAであることは**自分たちの設定** |
| 日足の構造 | D1の確定ピボット（`N_d1=3`、全履歴）、日足30SMA | 原典は「日足MA」と書くだけで期間なし。A基準の「日足MAまで距離」（`d1_ma_room`）と同じ D1 fast MA を使う＝**自分たちの設定** |
| 引き金のラインの除外 | 約定価格から `tp_zone_pct`（0.5%）以内の構造は除く（ブレイクした節そのもの） | 原典の第1目標は常にブレイクしたラインの先。幅は**自分たちの設定**（PH-06のゾーン±0.5%を転用） |

### 7-2. 決済の判定

- 約定足: §3-1・§3-2 と同じ判定を「残っている最も近い目標」に対して行う。目標が先と判定された場合は、
  その足（M15で解決した場合はそのM15足）で届いた目標をすべて決済し、残りは同じ順序で次のM15足・次の足へ。
  M15で解決できない・欠損のときは残り全量を曖昧SL（§3-3）。
- 約定足より後の足: SLに届けば残り全量をSL（目標に届いていても。§3-3の保守的扱いと同じ）。
  届かなければ、その足で届いた目標をすべて決済する。
- ギャップで目標を飛び越えた場合も約定価格は目標価格（従来と同じ保守的扱い）。
- 1トレードのR = Σ(比率 × 各部分の損益 / リスク)。
- `Trade.reason`: 全目標で決済 `target`、目標の一部の後にSL `partial_stop`、目標なしでSL `stop`／`stop_ambiguous`
  （一部利確後の曖昧も `stop_ambiguous`）、データ終端 `end_of_data`。各部分は `Trade.legs` に残す。
- `Params.split_targets=False` で従来の単一目標に戻る（比較用）。
- **既定値は False（2026-10-17）**。全期間でT1までのRRが中央値0.17R（原典の第1目標は1:1.8〜1:3）で、
  T1の定義が原典と一致していないため。照合が済むまで `split_targets=True` は明示したときだけ使う。

### 7-3. 「H4のライン」の定義（2026-10-17 改訂）

報告: `100億j_share/報告_20261017_T1定義の照合.md`

7-1の「H4の確定ピボット」（全ピボット）では、原典が利確先にしない小さな節まで拾っていた。原典記事のチャート
（2026-03-04・2026-01-13・2025-02-23）では、エントリーと利確ラインの間にあるH4の小さな高値・安値は
すべて無視され、ラインとして描かれているのは丸印で2〜3回の接触を示した線か、日足と重なる節だけだった。
原典本文の言葉から、H4のラインを次のどちらかに限る（MAの扱いは7-1のまま）。

| 種類 | 原典の言葉 | 条件 | 数値の出どころ |
|---|---|---|---|
| (a) 何度も止められたライン | 「何度も止められている高値ライン」（#1）、「3度高値をつけているライン」（#11）、「レジサポ転換ライン」（#8・#9、丸印2つ） | 「止められた」H4ピボット（高値・安値どちらでも）が、許容幅の中に2つ以上ある価格 | 「止められた」＝確定窓の中で1.0 ATR以上の反発（既存C基準の `strong_pivot_reaction_atr`）。許容幅＝0.4×H4 ATR（既存C基準の `k2`）。2つ以上＝既存 `line_touch_min`。**いずれも既存の設定値の転用** |
| (b) 日足と重なる節 | 「日足・4時間足レベルの直近高値ライン」（#4）、「日足・4時間足レベルの安値ライン」（#6）、「日足の戻り高値ライン＆4時間足80MA」（#3） | 「止められた」H4ピボットのうち、許容幅の中にD1の確定ピボットがあるもの | 同上 |

- ラインの価格は条件を満たしたH4ピボットの価格。そのあとの除外（0.5%）・重なり・手前・比率・T3は7-1と同じ。
- 届かない原典の型: 「前回上昇の起点となった過去の安値」（#5）、単独の「4時間足レベルの安値ライン」（#7）のような
  一回限りの大きな節は、(a)(b)のどちらにも入らない。単独の節の大きさを測る原典の言葉がないため、今回は入れない。

### 7-4. 「今の波の範囲」と「直下」（2026-10-17 改訂2）

報告: `100億j_share/報告_20261017_T1前の波の節.md`

7-1・7-3の「全履歴」と「0.3%手前」は、この節で置き換える。

**今の波の範囲（ラインを探す範囲）**: H4のラインは、注文時点から遡って **H4 180本**（約30日）の中で確定したピボット
だけで作る。日足の構造（(b)の照合とT3）も **D1 140本** の中の確定ピボットに限る。

- 理由: 7-3を全履歴のピボットで作ると、BTCが過去に同じ価格帯を通った年のピボットが重なり、ほぼすべての価格帯が
  「2回止められたライン」になっていた（2026-01-13のH4チャートで確認）。原典が引くラインは、記事に載せた
  そのときのH4チャートに見えている節だけで、原典のH4チャートの幅は約200本（2026-03-04 `27.png`、2026-01-13 `20.png`）。
- 本数: 既存の方向MAの期間（H4 180、D1 140）を転用（**自分たちの設定**。新しい数値は作っていない）。
- 押しの範囲の外だけを見る案（押しの底より後にできた節を除く）は、原典の図と合わないので**採らない**:
  2026-03-04 では利確ライン（3度高値）の丸印3つのうち2つが押しの底より後にできている。もみ合いの中の高値は、
  エントリーがそれをブレイクする形なので、既存の「引き金のライン」除外（約定価格から0.5%以内）で外れる。
- ③形の認識で再利用する場合: 「今の波の範囲」＝ `DecisionPipeline._wave_pivots(state, period)`
  （注文時点から遡って `period` 本の中の確定ピボット）。

**直下（手前の幅）**: 0（ラインの価格そのものに指値）。

- 理由: 原典の決済画像（2026-01-13 `25.png`・`26.png`）では決済ライン①②は丸印の高値にほぼ重なって引かれており、
  価格軸がないため幅は読めない。原典の言葉は「直下」（すぐ下）だけで、スプレッドのないOHLCモデルでは
  「すぐ下」とラインの価格は区別できない。SL bufferの転用（0.3%）はやめる。

### 7-5. F（エントリーの可否）をT1で判定する（2026-10-17 固定）

報告: `100億j_share/報告_20261017_F見送り基準.md`

> F は、**最初の利確先（T1）までのリスクリワードが 1:1 以上**なら合格。T1 は §7-1・7-3・7-4 の第1目標（注文時点の確定足、
> 近い節を飛ばさない）、リスクは §5-1 のSL（約定直前の最新の節）。

| 項目 | 規則 | 出どころ |
|---|---|---|
| 最低RR | 1.0 | 損切り記事8671「最低でもそのバランスが1：1以上の場合のみ…エントリー」。実例でも事前RR 1:1 の局面には入り（記事22285・19177「あまり良いとは言えず」）、1:1未満で入った記事は0本。従来の MinRR 1.5 は原典にない値 |
| 近いラインを飛ばさない | T1が近すぎてRRが1未満なら見送り | 原典定義2-1「レジスタンスラインなどがあまりにも近すぎる場合は…エントリーを見送り」。近いラインを飛ばして遠い目標でRRを計算する記事は0本 |
| T1がない（4時間足の節がない） | 日足の最も近い構造（今の波の範囲のD1ピボット・日足MA、§7-4）をT1とする | 原典の利確先は常に4時間足か日足の節（#3は日足の戻り高値） |
| それもない | 見送り（F不合格） | 原典は必ず利確先を名指ししてRRを計算する。利確先を言えない局面に入った記事はない |

- 決済（`Decision.target` と §7 の分割）はこの節では変えない。分割利確の既定値は §7-2 のまま。
- 下位足に落として損切りを狭くする（記事22707・23485など）は⑥・別の型であり、ここでは扱わない。
- `Params(f_uses_t1=False)` で従来（`_target` と MinRR 1.5）に戻る。

### 7-6. ③形: 1時間足の波が4時間足MAから始まる（2026-10-17 固定）

報告: `100億j_share/報告_20261017_形の認識.md`

> E（波の入れ子）は、従来の条件に加えて、**SLにしたH1の節（§5-1）が、その節の足の時点で4時間足MA相当（H1 80SMA）から
> 0.6×H1 ATR 以内**にあることを求める。

- 原典の言葉: 「4時間足の波を1時間足の波の最初から獲れることになりますので、それなりのリワードが見込める局面」（BTC記事11本のほぼすべて）、
  「4時間足MAに支えられて下髭をつけて伸びてきた」（2026-03-04）、「下向きの4時間足MAに頭を抑えられ」（2025-02-23）、
  SKILL ルール3「ワンクッショングランビル第3波」（10本中9本）。PDF p.184「1時間足レベルの損切り幅で4時間足レベルのリワードを獲る」。
- 原典の図: 2026-01-13（`20.png`）・2026-03-04（`27.png`）・2025-02-23 とも、SLの高さは4時間足MAとほぼ同じ。
- 実データの確認（定義を決めた後）: 2026-01-13 のSL 0.22、2026-03-04 の4時間足MAでの下髭の安値 0.10（H1 ATR単位）。
- 幅0.6×H1 ATR は既存B基準の `k1`（H1 20SMAがH4 MA相当に「近い」の幅）の転用（**自分たちの設定**）。同じ「4時間足MAに近い」という概念に同じ幅を使う。
- 距離はSLの節の足の時点のMA・ATRで測る（節は約定直前までに確定したもの。約定足の情報は使わない）。
- `Params(e_wave_from_h4_ma=False)` で従来のEに戻る。
