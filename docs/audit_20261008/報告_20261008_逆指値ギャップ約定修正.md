# 逆指値ギャップ約定の修正

2026-10-08 / Codex

## 実施した変更

音声で「一つずつ」「次にできることを」と依頼を受け、逆指値を飛び越えた際の約定処理を直す方針を提示し、「お願いします」と承認された範囲を実装した。

対象は `oku100/pipeline.py` の `_stop_entry_fill`。変更する戦略変数は約定価格だけ。

- 買い: `max(注文価格, 約定バー始値)`
- 売り: `min(注文価格, 約定バー始値)`
- 飛び越えのない通常のタッチは、従来どおり注文価格。
- 注文元のピボットを変更せず、約定記録に実際のモデル上の約定価格を保存する。
- 後段のエントリー価格・SL/TP選択・RR計算に、この価格が渡る。
- 診断表示を `trigger` から `fill_price` に変更し、注文ラインと約定価格を混同しないようにした。

これはOHLCを使った約定モデルの修正。スプレッド、追加スリッページ、実口座の約定保証までは扱っていない。

## 修正前後の検証

追加テスト: `tests/test_stop_gap_execution.py`（8件）。

修正前は、買いギャップ・売りギャップ・エントリー/RRへの価格伝達の3件が失敗し、問題が再現された。修正後は追加8件＋既存19件、合計27件が全通過した。

具体例:

| 例 | 修正前 | 修正後 |
|---|---|---|
| 買い注文101、次の始値105 | 101 | 105 |
| 売り注文99、次の始値95 | 99 | 95 |
| 買い注文101、始値100、足内で101到達 | 101 | 101 |

未到達なら未約定、注文を置いた同じ足では約定しない、二重約定しない、という動作も確認した。ギャップ後にentry105・SL98・TP120となる例では、RRが `(120-105)/(105-98)` に更新されることを確認した。

## 残っている問題

前回監査のうち、候補集計とバックテストの入口不一致、未確定情報の扱い、約定バー内決済、Cの支持線と抵抗線の混同、Fの近い障害を飛ばす処理は未修正。原典の型の定義・閾値も変更していない。今回のテスト成功は、原典の再現完成や収益性の証明ではない。

次の1項目は、逆指値約定の可否判定に約定バーの終値を使わないよう、注文時点・約定直前・足確定後の情報を分けること。入口の形を変える前に、情報の時点を揃える。
